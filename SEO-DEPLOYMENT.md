# Goat Journey SEO release

Branch: `codex/seo-entity-services`. Base: `687eefc75975b0ac250e45bf7314cee2201ac452`.

## Implemented

- A single site identity and canonical URL source; Wael Irzeqat / وائل أرزيقات is connected to Goat Journey through Person, EducationalOrganization and WebSite IDs. Unverified credentials, opening hours, coordinates and numeric claims were removed from the revised identity/service sections.
- Server rendering and shared cached public reads for lessons, articles, paths, homepage listings and site copy. The browser receives list summaries; lesson bodies are sent only for the selected lesson. Supabase errors fail explicitly; only an unconfigured local preview uses repository content. An intentionally empty database result stays empty.
- Page-specific canonical, description, Open Graph and Twitter metadata. Real PNG social card at `/og/default.png`. Dynamic lesson/article URLs use the same content source as their listing and metadata, redirect legacy IDs to canonical slugs, and return 404 for missing content.
- One robots route and a sitemap generated from the public content source. Personal/admin/auth pages are noindex; private pages are dynamic and excluded from sitemap. Public pages remain crawlable by search crawlers including OAI-SearchBot through the wildcard rule.
- Four distinct service pages, linked from the homepage, service hub, about page and consultation flow: `barista-training-palestine`, `coffee-consultant-palestine`, `cafe-staff-training`, `coffee-menu-development`. Visible FAQ answers, preparation, delivery scope and relevant reading; no invented pricing or accreditation.
- Search accepts `q`, filters current lesson data and finds articles, services and guides. Correct breadcrumb labels and links. Removed fake resource email gating and meaningless client-only CAPTCHA verification. The consultation flow opens a user-controlled WhatsApp/email draft; it does not claim to have sent a message.
- Server authorization on administration layout and data actions using `getUser()` and trusted `app_metadata.role`. Removed the plaintext password action/store and default login hints. SQL bootstrap templates now restrict writes and keep public reads explicit. Existing-install repair is in `fix-profiles-rls.sql`.
- Real data replaces simulated visit summaries. Optional GA4 page-view/contact-click events contain paths and service/channel labels, not consultation text or URL queries. Optional Google/Bing verification metadata is configured by environment.
- Responsive image handling, smaller shared lesson data, mobile header/navigation sizing and a service worker that caches only immutable Next static assets, never HTML, authenticated responses or APIs.

## Deploy in this order

1. Confirm the Supabase project URL used by the existing Goat Journey deployment. The connected project named **brew lab** was not assumed to be this project and was not changed. Copy the verified public URL and publishable/anon key into the deployment environment using `.env.local.example`; never expose a service-role key.
2. In the verified project's Auth administration, assign `app_metadata.role = "admin"` to the intended existing administrator through the trusted Admin API. `user_metadata` and `profiles.role` do not authorize administration. Refresh the user's session after changing the role.
3. Inspect existing RLS policies and take the normal project backup. Review/apply `fix-profiles-rls.sql` in that project's SQL editor. It updates known legacy policies and signup behavior, removes the obsolete password setting, and prints the policy inventory. It deliberately preserves unknown policies; review any other permissive policies before deployment. Do not run the bootstrap/seed SQL on an existing production database.
4. Verify database access with three roles: anonymous public content SELECT succeeds; anonymous and ordinary authenticated content/storage writes fail; the approved admin can manage content; each user's favorites/progress/settings remain isolated. Confirm the six public-copy keys are readable but all other `admin_settings` rows are protected. These live database checks require access to the correct project and were **not** performed locally.
5. Install from `package-lock.json` (`npm ci`), run `npm run build`, then `npm run start`. In another terminal run `npm run verify:seo -- http://localhost:3000`. For local seed edits run `node --import tsx scripts/generate-lesson-catalog.mjs` to refresh the lightweight badge/navigation catalog. No pnpm lock is included; npm remains the authoritative dependency lock.
6. Deploy the branch using the existing hosting configuration. Re-run the SEO verifier against the deployed URL, confirm the old broad `/services/*` redirects are gone, and check that the CDN/WAF allows Googlebot, Bingbot and OAI-SearchBot. Site code alone cannot override an upstream crawler block.
7. Add real `GOOGLE_SITE_VERIFICATION` / `BING_SITE_VERIFICATION` tokens when needed, verify ownership and submit `https://www.goatjourney.online/sitemap.xml` to the accounts. Inspect the home, about and four service URLs. Validate structured data with Google's tooling and Schema.org Validator. Monitor selected canonicals and indexing rather than assuming inclusion.
8. If enabling GA4, set `NEXT_PUBLIC_GA_MEASUREMENT_ID` before building. Disable enhanced measurement's automatic browser-history page views to avoid duplicate SPA events; review automatic form/search tracking in the account before enabling it. The included explicit events are `page_view` and `contact_click`; clicks are not confirmed leads. Compare Search Console impressions/clicks and qualified enquiries over subsequent weeks.
